🛒 Проектная работа «Web-Ларёк»

Web-Ларёк - интернет-магазин с товарами для веб-разработчиков.

Пользователь может:

* просматривать каталог товаров;
* открывать подробную информацию о товаре;
* добавлять товары в корзину;
* удалять товары из корзины;
* выбирать способ оплаты;
* указывать адрес доставки;
* вводить контактные данные;
* оформлять заказ;
* получать уведомление об успешном оформлении заказа.

🏗 Архитектура приложения

Приложение построено по архитектуре MVP (Model-View-Presenter).

Архитектура разделяет приложение на три основных слоя:

Model

Отвечает за хранение и изменение данных приложения.

View

Отвечает за отображение данных и взаимодействие пользователя с интерфейсом.

Presenter

Содержит основную логику приложения и связывает модели с представлением.

Для связи компонентов используется событийно-ориентированный подход с помощью брокера событий EventEmitter.

Общая схема взаимодействия:

                 ┌─────────────┐
                 │    Server   │
                 └──────┬──────┘
                        │
                        ▼
                 ┌─────────────┐
                 │ WebLarekApi │
                 └──────┬──────┘
                        │
                        ▼
                 ┌─────────────┐
                 │    Model    │
                 │             │
                 │ Products    │
                 │ Cart        │
                 │ Buyer       │
                 └──────┬──────┘
                        │
                        ▼
                 ┌─────────────┐
                 │  Presenter  │
                 └──────┬──────┘
                        │
                        ▼
                 ┌─────────────┐
                 │    View     │
                 │             │

                 │ Cards       │
                 │ Forms       │

⚙️ Базовые компоненты

Component

Базовый класс для компонентов интерфейса.

Класс является дженериком и принимает тип данных T, которые могут быть переданы в метод render.

Конструктор

constructor(container: HTMLElement)

Принимает корневой DOM-элемент компонента.

Поля

* container: HTMLElement - корневой DOM-элемент компонента.

Методы

render(data?: Partial<T>): HTMLElement

Записывает переданные данные в свойства компонента через сеттеры и возвращает корневой DOM-элемент.

setImage(
    element: HTMLImageElement,
    src: string,
    alt?: string
): void

Устанавливает изображение и альтернативный текст для элемента <img>.

⸻

Api

Базовый класс для работы с HTTP-запросами.

Конструктор

constructor(
    baseUrl: string,
    options: RequestInit = {}
)

Принимает базовый URL API и дополнительные параметры запроса.

Поля

* baseUrl: string - базовый адрес API.
* options: RequestInit - настройки запросов.

Методы

get<T>(uri: string): Promise<T>

Выполняет GET-запрос.

post<T>(
    uri: string,
    data: object,
    method: ApiPostMethods = 'POST'
): Promise<T>

Отправляет данные на сервер в формате JSON.

handleResponse<T>(response: Response): Promise<T>

Проверяет ответ сервера и возвращает данные либо отклоняет Promise при ошибке.

⸻

EventEmitter

Брокер событий, реализующий паттерн Наблюдатель (Observer).

Используется для связи моделей, представлений и Presenter.

Основные методы

on(event, callback)

Подписывает обработчик на событие.

emit(event, data?)

Вызывает событие и передаёт данные подписчикам.

trigger(event, context?)

Создаёт функцию-триггер для указанного события.

📊 Данные приложения

IProduct

Описывает товар.

interface IProduct {
    id: string;
    description: string;
    image: string;
    title: string;
    category: string;
    price: number | null;
}

Поля

* id - уникальный идентификатор товара.
* description - описание товара.
* image - путь к изображению.
* title - название товара.
* category - категория товара.
* price - стоимость товара.

Если price равен null, товар недоступен для покупки.

⸻

IBuyer

Описывает данные покупателя.

interface IBuyer {
    payment: TPayment;
    email: string;
    phone: string;
    address: string;
}

Поля

* payment - способ оплаты.
* email - электронная почта.
* phone - номер телефона.
* address - адрес доставки.

Тип оплаты:

type TPayment = 'card' | 'cash';

⸻

🧠 Модели данных

ProductModel

Отвечает за хранение каталога товаров и выбранного товара.

Поля

* products: IProduct[] - список товаров.
* preview: IProduct | null - выбранный товар для подробного просмотра.

Методы

setProducts(products: IProduct[]): void

Сохраняет каталог товаров.

getProducts(): IProduct[]

Возвращает каталог товаров.

getProduct(id: string): IProduct | undefined

Возвращает товар по идентификатору.

setPreview(product: IProduct): void

Устанавливает товар для предварительного просмотра.

getPreview(): IProduct | null

Возвращает выбранный товар.

⸻

CartModel

Отвечает за состояние корзины.

Поля

* items: IProduct[] - товары в корзине.

Методы

getItems(): IProduct[]

Возвращает товары корзины.

add(product: IProduct): void

Добавляет товар в корзину.

remove(product: IProduct): void

Удаляет товар из корзины.

clear(): void

Очищает корзину.

getTotal(): number

Возвращает общую стоимость товаров.

getCount(): number

Возвращает количество товаров в корзине.

hasProduct(id: string): boolean

Проверяет наличие товара в корзине.

⸻

BuyerModel

Отвечает за хранение и изменение данных покупателя.

Поля

* payment - выбранный способ оплаты.
* email - электронная почта.
* phone - номер телефона.
* address - адрес доставки.

Методы

setData(data: Partial<IBuyer>): void

Обновляет переданные данные покупателя.

getData(): IBuyer

Возвращает данные покупателя.

clear(): void

Очищает данные покупателя.

validate(): TValidationErrors

Проверяет корректность заполнения данных и возвращает ошибки валидации.

🌐 Слой коммуникации

WebLarekApi

Отвечает за взаимодействие приложения с сервером.

Использует базовый класс Api.

Конструктор

constructor(api: IApi)

Получает объект API для выполнения запросов.

Методы

Получение товаров

getProducts(): Promise<IProductsResponse>

Запрос:

GET /product/

Получает каталог товаров с сервера.

Создание заказа

createOrder(data: IOrderRequest): Promise<IOrderResponse>

Запрос:

POST /order/

Отправляет данные оформленного заказа на сервер.

🖥 Слой представления (View)

View отвечает за отображение данных и взаимодействие пользователя с интерфейсом.

Компоненты View не работают напрямую с моделями и API. При действиях пользователя они генерируют события, которые обрабатывает Presenter.

⸻

Header

Отвечает за отображение шапки сайта и счётчика товаров в корзине.

Поля

* basketButton - кнопка открытия корзины.
* counterElement - счётчик товаров.

Методы

set counter(value: number): void

Обновляет количество товаров в корзине.

При нажатии на корзину генерируется:

basket:open

⸻

Gallery

Отвечает за отображение каталога товаров.

Конструктор

constructor(container: HTMLElement)

Методы

set catalog(items: HTMLElement[]): void

Устанавливает карточки товаров в каталоге.

⸻

Card

Базовый класс для карточек товаров.

От него наследуются:

* CatalogCard
* PreviewCard
* BasketCard

Поля

* titleElement - название товара.
* categoryElement - категория товара.
* imageElement - изображение товара.
* priceElement - цена товара.

Методы

set title(value: string): void
set category(value: string): void
set image(value: string): void
set price(value: number | null): void

⸻

CatalogCard

Отвечает за отображение товара в каталоге.

При нажатии на карточку генерируется событие:

card:select

Оно открывает подробную информацию о товаре.

⸻

PreviewCard

Отображает подробную информацию о товаре в модальном окне.

Поля

* descriptionElement - описание товара.
* button - кнопка покупки.

Методы

set description(value: string): void

Устанавливает описание товара.

При нажатии на кнопку генерируется:

card:buy

⸻

BasketCard

Отображает товар внутри корзины.

Поля

* indexElement - порядковый номер товара.
* button - кнопка удаления.

При удалении товара генерируется:

basket:remove

⸻

Basket

Отвечает за отображение содержимого корзины.

Поля

* listElement - список товаров.
* totalElement - общая стоимость.
* button - кнопка оформления заказа.

Методы

set items(value: HTMLElement[]): void

Устанавливает список товаров.

set total(value: number): void

Устанавливает общую стоимость.

При нажатии на кнопку оформления заказа:

order:open

⸻

Modal

Отвечает за управление модальными окнами.

Поля

* content - содержимое модального окна.
* closeButton - кнопка закрытия.

Методы

set content(value: HTMLElement): void

Устанавливает содержимое модального окна.

open(): void

Открывает модальное окно.

close(): void

Закрывает модальное окно.

render(data?: object): HTMLElement

Отображает содержимое и возвращает DOM-элемент.

При закрытии генерируется:

modal:close

⸻

Form

Базовый класс для форм.

От него наследуются:

* OrderForm
* ContactsForm

Поля

* submitButton - кнопка отправки.
* errorsElement - элемент для отображения ошибок.

Методы

Устанавливает доступность кнопки отправки.

OrderForm

Первый этап оформления заказа.

Пользователь:

1. выбирает способ оплаты;
2. вводит адрес доставки.

Поля

* cardButton - оплата картой.
* cashButton - оплата при получении.

Методы

Устанавливает выбранный способ оплаты.

При выборе оплаты:

При отправке формы:

order:submit

⸻

ContactsForm

Второй этап оформления заказа.

Пользователь вводит:

* email;
* номер телефона.

При изменении данных генерируется:

contacts:change

При отправке формы:

contacts:submit

⸻

Success

Отображает результат успешного оформления заказа.

Поля

* totalElement - информация о списанной сумме.
* closeButton - кнопка перехода к дальнейшим покупкам.

Методы

set total(value: number): void

Отображает сумму заказа.

После нажатия на кнопку генерируется:

success:close

⸻

🎯 Presenter

Presenter является связующим звеном между Model и View.

Он:

* обрабатывает события интерфейса;
* изменяет состояние моделей;
* запускает перерисовку интерфейса;
* выполняет валидацию данных;
* формирует заказ;
* отправляет заказ через API;
* очищает корзину после успешной покупки;
* отображает окно успешного заказа.

Основной поток оформления заказа:

Пользователь
     │
     ▼
Корзина
     │
     ▼
Выбор способа оплаты
     │
     ▼
Адрес доставки
     │
     ▼
Контактные данные
     │
     ▼
Presenter
     │
     ▼
WebLarekApi
     │
     ▼
Server
     │
     ▼
Успешный заказ
     │
     ├──► Очистка корзины
     ├──► Очистка данных покупателя
     ├──► Обнуление счётчика
     └──► Окно успешного заказа

API
 ↓
WebLarekApi
 ↓
ProductModel
 ↓
Presenter
 ↓
Gallery
 ↓

2. Добавление товара

CatalogCard
 ↓
card:buy
 ↓
Presenter
 ↓

 ↓
basket:changed
 ↓
Header + Basket

3. Оформление заказа

Basket
 ↓
OrderForm
 ↓
ContactsForm
 ↓
Presenter
 ↓
WebLarekApi
 ↓
POST /order/
 ↓
Success

4. После успешного заказа

Успешный ответ сервера
        ↓
Очистка CartModel
        ↓
Очистка BuyerModel
        ↓
Счётчик корзины = 0
        ↓
Окно успешного заказа

✅ Итог

Проект реализует полный пользовательский сценарий интернет-магазина:

каталог → просмотр товара → корзина → оформление заказа → отправка на сервер → успешный заказ.

Архитектура MVP позволяет разделить ответственность между данными, интерфейсом и бизнес-логикой, а событийная модель делает взаимодействие компонентов независимым и удобным для расширения.
